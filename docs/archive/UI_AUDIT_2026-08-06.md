## 1. The core problem: two colour systems running in parallel

The app has a genuinely well-built token system — 7 themes, ~40 CSS custom
properties, semantic type scale, `--brand`/`--brand-fg` pairs, a chart palette.
Roughly 80% of the UI consumes it correctly.

The other 20% bypasses it entirely:

| Escape hatch | Count | Files |
|---|---|---|
| Hardcoded Tailwind palette (`bg-amber-50`, `text-red-600`, …) | **559** | 61 |
| Arbitrary hex classes (`bg-[#fafbfc]`, `text-[#1A7F37]`, …) | **61** | 20 |
| `text-white` on a `--brand` background | 7 | 5 |
| `dark:` variants | 20 | 6 |

All of these are light-palette values. They are invisible on the two light
Auroras and Classic, and wrong on Gilded Noir, Aurora Dark, Notion, and Clay.

### 1.1 The remap only covers Aurora, and only partially

`globals.css:1193–1318` remaps hardcoded palette classes back onto tokens — but
the selectors are scoped to `:root.theme-aurora-dark` / `:root.theme-aurora-light`
only. **Gilded Noir is also a dark theme and gets none of it.** Notion and Clay
get none of it.

Even under Aurora the remap is incomplete. It covers `-50/100` backgrounds,
`border-*-200/300`, and `text-*-600..900`. Not covered, but in use:

- `bg-emerald-500` ×12, `bg-blue-500` ×11, `bg-red-500` ×7, `bg-amber-500` ×5,
  `bg-amber-400` ×5, `bg-red-400` ×4
- `text-green-500` ×4, `text-amber-500` ×4, `text-red-500` ×6, `border-red-500` ×5
- **Every `slate`/`gray`/`zinc` class** — `text-gray-900`, `bg-slate-100`,
  `bg-gray-100`, `border-gray-200`, `bg-slate-400`, `bg-gray-400`

Visible consequence, [AiSettings.tsx:26](frontend/web/src/features/admin/AiSettings.tsx:26):
the model tag row renders `most capable` / `fastest` / `reasoning` correctly
themed (their `-50/700/200` classes are remapped) while `stable` / `base` /
`legacy` / `default` stay light-grey chips, because `bg-gray-100` isn't in the
remap list. Same row, two different colour systems.

### 1.2 `dark:` variants are wired to the OS, not to the theme

20 usages across 6 files. There is **no `@custom-variant dark` and no `darkMode`
config anywhere** in the project. In Tailwind v4 the default `dark` variant is
`@media (prefers-color-scheme: dark)`, so these key off the operating system and
are completely decoupled from which of the 7 themes is active.

Both failure directions are live:
- Aurora Light + OS dark → dark banner styling on a light page
- Gilded Noir + OS light → light banner styling on a dark page

Worst instance, [settings/account/page.tsx:65](frontend/web/src/app/\(dashboard\)/settings/account/page.tsx:65):
`text-black dark:text-white` — black text on a dark card whenever the OS is set
to light.

Also in: `EmailIntegrationCard.tsx:44,98`, `LibraryCards.tsx:97`,
`ReviewComponents.tsx:35,45`, `ResumePausedBanner.tsx:33,34,41`.

### 1.3 `text-white` where `--brand-fg` is required

`--brand-fg` exists precisely so a CTA's label contrasts with its brand fill. It
is **dark** on two themes: Gilded Noir `#3C2F00` (gold fill) and Aurora Dark
`#04231F` (bright teal fill). Seven places hardcode `text-white` instead:

- [FeedCards/shell.tsx:171,187](frontend/web/src/features/jobs/components/FeedCards/shell.tsx:171) — the card's **Apply** and **Analyse** buttons
- [detail/DetailHeader.tsx:404,408,415,422](frontend/web/src/features/jobs/components/detail/DetailHeader.tsx:404)
- [SetupGateClient.tsx:122](frontend/web/src/components/providers/SetupGateClient.tsx:122)

White on Gilded Noir's `#F2CA50` is ~1.9:1; on Aurora Dark's `#19E3C8` ~1.6:1.
Both fail WCAG badly, and these are the app's primary actions.

Same bug in the checkbox/radio glyphs at
[SmartToolbar.tsx:137–138](frontend/web/src/features/jobs/components/SmartToolbar.tsx:137)
and the select-mode tick at
[FeedCards/shell.tsx:311](frontend/web/src/features/jobs/components/FeedCards/shell.tsx:311).

## 2. Specific high-impact defects

### 2.1 The detail pane's tab strip is a hardcoded white band
[BoardDetailPanel.tsx:258](frontend/web/src/features/jobs/components/detail/BoardDetailPanel.tsx:258) — `bg-[#fafbfc]`.

Arbitrary hex isn't in any remap. On Aurora Dark and Gilded Noir this paints a
near-white strip across the detail pane with `text-text-2` (light grey) tab
labels on it — effectively unreadable. Same hex in
`CoverLetterTab.tsx:85,96,231`, `ApplyModal.tsx:485,542`,
`MatchScoreTab.tsx:121,127`.

### 2.2 `SourcePill` — the wrong implementation shipped, the right one is dead
[chips.tsx:165](frontend/web/src/features/jobs/components/FeedCards/chips.tsx:165)
hardcodes `bg-[#f0f1f4]` with `text-text-2`. That's on **every job card**. On
Aurora Dark it's light-grey text on a near-white pill (~1.7:1).

Meanwhile [smartFeedUtils.ts:54](frontend/web/src/features/jobs/lib/smartFeedUtils.ts:54)
contains `sourcePillTone()` — a fully tokenised per-source palette
(`--brand`/`--teal`/`--purple`/`--amber`) that is **never imported anywhere**.
The correct implementation exists and was never wired up.

### 2.3 Auth pages inherit the user's theme, then fight it
The FOUC script in [layout.tsx:137](frontend/web/src/app/layout.tsx:137) is in the
**root** layout and runs unconditionally — including on `/auth/*`. So `<html>`
carries `theme-aurora-dark` on the login page for anyone who picked it.

The auth screens are hardcoded Classic hex, but they compose the shared `Input`,
which uses `.field` (`var(--surface)`, `var(--text)`, `var(--border)`) and
`FieldLabel`, which uses `text-text`. Result for a signed-out Aurora Dark user:

- dark input boxes inside a hardcoded `#FFFFFF` card
- `--text` `#EAEEF6` labels → **white text on the white card**

[brand.tsx:1–9](frontend/web/src/features/auth/components/brand.tsx:1) explicitly
claims these pages "do NOT consume the app theme tokens directly — they render
the same way regardless of a logged-in user's own theme choice." That is not true
of the fields.

### 2.4 ATS band colours — the primary scoring signal — are raw palette
[smartFeedUtils.ts:21](frontend/web/src/features/jobs/lib/smartFeedUtils.ts:21).
`ATS_BAND_META` is entirely `bg-green-500` / `bg-amber-500` / `bg-red-500` /
`bg-gray-300` / `bg-gray-400`, driving the dot, chip and bar on every card. None
of the `-300/400/500` values are remapped on any theme. `globals.css:1055–1102`
defines a `--chart-*` palette for exactly this and it goes unused here.

### 2.5 Two sidebar nav items can never show as active
[SidebarLinks.tsx:378–379](frontend/web/src/components/navigation/SidebarLinks.tsx:378):

```
<NavItem href="/dashboard?stage=favourite" …>Favourite</NavItem>
<NavItem href="/dashboard?stage=applied"  …>Applied</NavItem>
```

`NavItem` matches with `usePathname().startsWith(href)`. `usePathname()` returns
`/dashboard` with no query, so `"/dashboard".startsWith("/dashboard?stage=favourite")`
is always `false`. Neither item ever highlights, on any route.

### 2.6 A per-page query whose result is thrown away
[Sidebar.tsx:44–50](frontend/web/src/components/navigation/Sidebar.tsx:44) runs a
`jobs` query on **every dashboard page load** to compute unseen counts per
profile, threads it through as `Profile.newCount`, and
[SidebarLinks.tsx:312–335](frontend/web/src/components/navigation/SidebarLinks.tsx:312)
never renders it. The profile rows show a name and an activity icon only.

### 2.7 The location filter box keeps stale text after being cleared
[SmartToolbar.tsx:360–386](frontend/web/src/features/jobs/components/SmartToolbar.tsx:360).
The input is uncontrolled (`defaultValue` + `onBlur`). Clearing the filter — via
the token ✕ at line 480 or the inline ✕ at line 378 — updates the URL and removes
the chip, but React does not reset an uncontrolled input on re-render, so the old
search text stays visible in a box that is no longer filtering anything.

### 2.8 A documented cascade trap, hit anyway
[ResumePausedBanner.tsx:41](frontend/web/src/features/profiles/components/ResumePausedBanner.tsx:41)
passes `border-amber-300 … hover:bg-amber-100` to `<Button>` via `className`.

`Button` renders `.gh-btn`, which sets `border` and `background` in
**unlayered** CSS ([globals.css:458](frontend/web/src/app/globals.css:458)).
Unlayered rules beat layered Tailwind utilities regardless of specificity — the
comment above that rule says so in as many words. Every colour override on this
button is silently dead; it renders as a plain default button.

### 2.9 Invalid HTML in the root error boundary
[error.tsx:30–32](frontend/web/src/app/error.tsx:30) nests `<Button>` (a
`<button>`) inside `<Link>` (an `<a>`). `Button` has an `asChild` prop for exactly
this case. Two further issues in the same file: raw `error.message` is rendered
to end users, and "Go home" targets `/dashboard` even though this boundary also
covers the landing and auth routes (signed-out users get bounced to login).

### 2.10 Board layout uses fixed `100vh` inside a scrolling page
[SmartFeed.tsx:486,527](frontend/web/src/features/jobs/components/SmartFeed.tsx:486)
— `height: calc(100vh - 2rem)` on both columns. Below `lg` the master column is
full-width, so a 100vh inner scroller sits inside the already-scrolling main
column: two scrollbars, and `BulkActionBar` (sticky to the inner container's
bottom) lands below the fold. `100vh` also over-measures on mobile browsers —
`100dvh` is the fix.

### 2.11 Selection accent ignores the theme
[FeedCards/shell.tsx:327–333](frontend/web/src/features/jobs/components/FeedCards/shell.tsx:327)
hardcodes `#2563eb` for the selected/active card border and ring, and `#22c55e`
for the applied-job left accent. Blue selection highlights on Clay (pink),
Gilded Noir (gold) and both Auroras (teal).

Same pattern in [StatCards.tsx:147,149](frontend/web/src/features/dashboard/StatCards.tsx:147)
(`#1A7F37`) and [ProfilesTable.tsx:104,150,159](frontend/web/src/features/profiles/components/ProfilesTable.tsx:104).

## 3. Accessibility

- **Fake buttons.** `role="button"` on `div`/`span` in
  [StatCards.tsx:107,143,155](frontend/web/src/features/dashboard/StatCards.tsx:107),
  [PipelineDonut.tsx:498](frontend/web/src/features/dashboard/PipelineDonut.tsx:498),
  [LibraryCards.tsx:195](frontend/web/src/features/cv/library/LibraryCards.tsx:195).
  StatCards' handler doesn't `preventDefault()` on Space, so keyboard activation
  also scrolls the page. `LibraryCards` gets this right; `StatCards` doesn't.
- **Orphan tabs.** [SmartToolbar.tsx:513](frontend/web/src/features/jobs/components/SmartToolbar.tsx:513)
  gives `TabButton` `role="tab"` + `aria-selected`, but the wrapper is a plain
  `<div className="flex …">` — no `role="tablist"`, no `aria-controls`. Invalid
  ARIA; screen readers announce tabs with no tab list.
- **Invalid menu nesting.** [SmartToolbar.tsx:73–99](frontend/web/src/features/jobs/components/SmartToolbar.tsx:73)
  sets `aria-haspopup="true"` and renders `role="menuitemradio"` children inside a
  panel with no `role="menu"`.
- **Unreachable canvas.** [PipelineDonut.tsx:459](frontend/web/src/features/dashboard/PipelineDonut.tsx:459)
  — clickable `<canvas>` with no `role`, `aria-label`, or keyboard path. The
  legend beside it is keyboard-reachable, so the data is available; the chart
  itself isn't.
- **Sidebar resizer.** [ResizableSidebar.tsx:74–84](frontend/web/src/components/navigation/ResizableSidebar.tsx:74)
  — `role="separator"` with no `tabIndex`, `aria-valuenow`, or key handling, and
  mouse-only (no touch).

## 4. Landing page

### 4.1 Testimonials are presented as real
[page.tsx:411–431](frontend/web/src/app/page.tsx:411) renders three named people
("Aditya R.", "Wei L.", "Priya M.") with quotes, roles and cities, under the
heading **"Early users"** and the subhead **"Real feedback from people who
stopped manually refreshing Seek every morning."**

The JSON-LD block 350 lines up ([page.tsx:39–43](frontend/web/src/app/page.tsx:39))
says the opposite in a code comment: *"the on-page testimonials are illustrative,
not verified, and fabricating rating schema is both dishonest and a Google
penalty risk"* — and correctly omits `aggregateRating` for that reason.

So the schema was kept honest while the visible page asserts the quotes are real.
For an Australian-facing paid product that's ACL misleading-conduct exposure, and
it sits two sections below a feature card titled **"Honesty-guarded."** This is
the one finding here I'd treat as blocking regardless of what else gets done.

### 4.2 Section nav is unreachable on mobile
[landing.css:552](frontend/web/src/app/landing.css:552):
`.land-nav-links li:not(:last-child):not(:nth-last-child(2)) { display: none; }`
hides *How it works · Tailoring · Features · Sources · FAQ* below 720px, keeping
only Sign in / Get started. There is no hamburger or alternative. On a phone the
entire page structure is scroll-only.

### 4.3 Anchor jumps land under the sticky nav
`scroll-margin-top: 80px` is set on `.landing` — the container
([landing.css:7](frontend/web/src/app/landing.css:7)) — not on the `#how`,
`#tailor`, `#features`, `#sources`, `#faq` targets. `scroll-margin` only applies
to the element actually being scrolled to, so the 60px sticky nav covers each
section heading on every in-page jump.

### 4.4 Smaller landing items
- `.land-pill-green` ([landing.css:336](frontend/web/src/app/landing.css:336)) is
  **blue** — it uses `--accent`. The "Sponsored · 482" pill therefore reads blue,
  and only the amber PR-only pill is visually differentiated. The class name says
  green and the semantic intent is green.
- The final CTA's `em` is `#19E3C8` ([landing.css:485](frontend/web/src/app/landing.css:485))
  — Aurora Dark's teal, on an otherwise entirely blue page. Leftover.
- Footer links Privacy but **not Terms**, though `/terms` exists. Neither nav nor
  footer links `/pricing`, though it exists and the JSON-LD `offers.url` points at it.
- Source count disagrees with auth: landing says "6 Live AU sources" / "Six
  sources"; every auth screen's trust strip says "5 AU sources".

## 5. Auth

Consistent, well-built screens — and the most token-hostile code in the repo.

- **~40 hardcoded hex values** across `Shell.tsx`, `LoginForm`, `SignupForm`,
  `ForgotPasswordForm`, `UpdatePasswordForm`, `PasswordRequirements`, `brand.tsx`.
  Almost all inline `style={{}}`, so not even reachable by a CSS override.
- **Leftover Aurora teal.** `rgba(11, 125, 116, …)` is `#0B7D74` — Aurora Light's
  brand. It survives as the *background* of three success affordances, each with
  **blue** `#3B82F6` content inside it:
  [LoginForm.tsx:114](frontend/web/src/features/auth/components/LoginForm.tsx:114) (email-confirmed notice),
  [SignupForm.tsx:145](frontend/web/src/features/auth/components/SignupForm.tsx:145) (check-your-inbox circle),
  [ForgotPasswordForm.tsx:150](frontend/web/src/features/auth/components/ForgotPasswordForm.tsx:150) (reset-sent circle).
  Teal-tinted circles with blue icons.
- **No Terms/Privacy consent link on signup at all**, for a flow that requires a
  card. Both pages exist.
- **Contradictory trial copy.** Signup says *"3-day free trial — no commitment
  required"* ([SignupForm.tsx:192](frontend/web/src/features/auth/components/SignupForm.tsx:192));
  the landing FAQ says *"A card is required to start the trial"*
  ([page.tsx:392](frontend/web/src/app/page.tsx:392)). Both are on the path to the
  same checkout.
- **No show/hide toggle** on any of the four password fields.
- [LoginForm.tsx:158](frontend/web/src/features/auth/components/LoginForm.tsx:158)
  passes `label=""` to `Input` and relies on `""` being falsy to suppress the
  label, because the real label is rendered outside to sit next to "Forgot
  password?". Works; fragile.

## 6. Consistency and drift

- **Type scale ~80% migrated.** 1050 semantic uses (`text-body`, `text-title`, …)
  vs 143 legacy (`text-xs/sm/base/lg/xl/…`) and 103 raw `text-[Npx]`. Stragglers
  are `terms/page.tsx` (22), `billing/page.tsx` (14), `privacy/page.tsx` (11),
  `voice/StoriesClient.tsx` (10), `billing/PlanCards.tsx` (8).
- **`themes.ts` docblock says "Five themes total"** and lists five
  ([themes.ts:4](frontend/web/src/lib/themes.ts:4)). There are seven — both
  Auroras are missing from the doc.
- **Root `CLAUDE.md` says auth pages hardcode the "Aurora Light palette."** They
  hardcode Classic. (The stray teal in §5 is the residue of the switch.)
- **`getStoredTheme()` falls back to `"classic"`, `applyTheme()` falls back to
  `"default"`** ([themes.ts:129,134](frontend/web/src/lib/themes.ts:129)) — two
  different fallbacks for the same invalid-value case.
- **Theme picker grid is `sm:grid-cols-2` for 7 items** → the last card is always
  orphaned on its own row. The selected-check glyph is `stroke="white"` on
  `preview.primary`, which is `#F2CA50` gold on Gilded Noir (~1.9:1).
- **Orphan comment** in `SidebarLinks` Props: *"Count of completed-letter jobs
  awaiting the To-review pool decision"* sits above `favouriteCount`
  ([SidebarLinks.tsx:57](frontend/web/src/components/navigation/SidebarLinks.tsx:57)),
  left over from the removed `/applications` screen.
- **`Button variant="primary"`** (deprecated alias of `brand`) still in use, e.g.
  [BulkActionBar.tsx:46,76](frontend/web/src/features/jobs/components/BulkActionBar.tsx:46).
- **Dead branch:** [SmartFeed.tsx:493](frontend/web/src/features/jobs/components/SmartFeed.tsx:493)
  passes `favourite={isFavouriteFilter}` to `EmptyState`, but `stage=favourite`
  always routes through `isFlatStage` above, so it is always `false` there.
- **Duplicate sign-out** on mobile: one in the `Header` bar
  ([Header.tsx:13](frontend/web/src/components/navigation/Header.tsx:13)) and one
  in the drawer's `UserFooter`.
- **Sidebar "Saved" never auto-expands.** `useState(false)` with no sync to the
  active route ([SidebarLinks.tsx:200](frontend/web/src/components/navigation/SidebarLinks.tsx:200)),
  so landing on `/profiles/:id/jobs` shows the group highlighted but collapsed.
- **Running-profile dot is `#22C55E` hardcoded**
  ([SidebarLinks.tsx:330](frontend/web/src/components/navigation/SidebarLinks.tsx:330))
  rather than `var(--green)`.
- **Light-mode-only shadows** — `hover:shadow-[0_2px_10px_rgba(16,24,40,0.07)]` on
  job cards and applied rows is invisible on every dark theme; nothing replaces it.

## Suggested sequencing

If the goal is maximum visible improvement per unit of risk:

1. **Contrast/legibility fixes** — `text-white` → `var(--brand-fg)` (7 sites),
   `bg-[#fafbfc]` tab strips (7 sites), `SourcePill` → wire up the existing
   `sourcePillTone()`, `ATS_BAND_META` → `--chart-*`. Small diffs, fixes the
   loudest breakage on Aurora Dark and Gilded Noir.
2. **Landing testimonials** — relabel as illustrative or remove. Independent of
   everything else, and the only item with legal exposure.
3. **Behavioural bugs** — sidebar active-state (2.5), stale location input (2.7),
   dead sidebar query (2.6), `ResumePausedBanner` button (2.8), `error.tsx` (2.9).
4. **`dark:` variants** — either add `@custom-variant dark (&:where(.theme-aurora-dark, .theme-gilded-noir, *))`
   to bind them to the theme classes, or delete all 20 and use tokens. Pick one;
   the current state is neither.
5. **Systemic palette migration** — the 559 + 61 hardcoded values. Best done per
   feature folder, and worth doing *after* 1–4 so it isn't blocking anything.
   Admin pages (`AiSettings`, `sourcing`, `activity`, `pipeline`, `quality`) are
   the densest and the lowest-traffic, so they can go last.
6. **Accessibility pass** — fake buttons, tablist wiring, canvas labelling.
7. **Landing mobile nav + anchor offsets**, auth tokenisation, type-scale tail.
